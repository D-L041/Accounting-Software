# Deployment preparation

Precious SchoolBooks is split into a static React frontend and a Django API backed by PostgreSQL.

## Container/API

The repository includes a production-oriented Dockerfile and Procfile. CI builds the API container on every pull-request update. For local development, run `docker compose up --build` from the repository root, then run the Vite frontend from `frontend` with `VITE_API_BASE_URL=http://localhost:8000`. The image installs the WSGI server, serves Django static assets through WhiteNoise, and exposes `/api/health/` as a database-aware health check.

Required runtime environment variables:

- `SECRET_KEY`: unique high-entropy secret generated by the hosting provider.
- `DEBUG=False`.
- `ALLOWED_HOSTS`: API hostnames only, comma-separated.
- `DATABASE_URL`: managed PostgreSQL connection string.
- `CORS_ALLOWED_ORIGINS`: exact HTTPS frontend origin(s), comma-separated.
- `CSRF_TRUSTED_ORIGINS`: exact HTTPS frontend origin(s), comma-separated.

Use a separate database and credentials for staging and production. Run `python manage.py migrate --noinput` as a controlled release/pre-deploy step, not as an unreviewed request-time operation. Static assets are collected during the container build.

## Frontend

Deploy the `frontend` directory as a Vite project. Build command: `npm run build`; output directory: `dist`. Set `VITE_API_BASE_URL` to the HTTPS origin of the Django API. The browser must be able to send credentialed requests to that exact origin.

## Domain and TLS

The school-owned domain has not yet been supplied in this repository's deployment configuration. Once confirmed, attach the frontend hostname to the frontend project and an API hostname (for example, `api.<school-domain>`) to the API host. Configure the exact origins in both CORS and CSRF environment variables, verify DNS and HTTPS, then test login, CSRF rotation, session cookies and logout from the real browser origin.

## Production release gates

- Provision managed PostgreSQL with automated backups and point-in-time recovery where available.
- Generate and store secrets in the host's secret manager; never commit them.
- Apply migrations and verify `/api/health/`.
- Confirm secure cookies, HTTPS redirect, HSTS, host allow-list and exact CORS/CSRF origins.
- Run cross-school permission tests and a production smoke test with synthetic records.
- Perform a restore drill before importing live school data.
- Do not use the system for live records until the release checklist is approved.
